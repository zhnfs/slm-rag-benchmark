# Proof of Concept: Fine-Tuned SLM vs. Frontier Model for Domain RAG

**Project Location:** `/Users/hainingzheng/pythonCodes/slm-rag-benchmark/`

This implementation plan details the steps to build a definitive benchmark comparing a localized, task-tuned Small Language Model against a frontier cloud model (Gemini) using your existing Oil & Gas dataset (copied from `ssrag-i2k-qwen3.5-2B`).

The objective is to definitively demonstrate that for RAG-based extraction, a specialized SLM provides superior latency, guaranteed data privacy, lower cost, and equivalent accuracy compared to a generalized cloud API.

## Proposed Changes

### 1. Data Preparation (Synthetic QA Generation)

We will copy your domain texts (e.g., `Artificial_lift.txt`, `Directional_drilling.txt`) from `/Users/hainingzheng/pythonCodes/ssrag-i2k-qwen3.5-2B/data/documents/` into `slm-rag-benchmark/data/documents/`.

#### [NEW] `slm-rag-benchmark/scripts/generate_rag_dataset.py`
A script that uses Gemini (via `litellm` or `google-genai`) to chunk your document text and generate ~200-300 synthetic QA pairs formatted exactly for LLaMA-Factory. 
*   **Format:** The prompt will include `[CONTEXT: {chunk}]` and the expected output will be the precise extraction.
*   **Output:** Writes `datasets/train.json` and `datasets/test.json`.

### 2. Fine-Tuning the SLM (LLaMA-Factory)

We will leverage your existing LLaMA-Factory setup to fine-tune the model to strictly adhere to the RAG context and never hallucinate outside of it.

#### [NEW] `slm-rag-benchmark/configs/rag_finetune.yaml`
A LLaMA-Factory configuration file targeting `Qwen/Qwen2.5-0.5B-Instruct` using LoRA.
*   **Optimization:** Configured for MPS (Mac M1), using small batch sizes to fit in 8GB VRAM.
*   **Training will use the LLaMA-Factory installation from your existing `finetune_slm_llamaFactory` venv.**

### 3. Benchmarking Suite

We will build an evaluation script that runs a test set of 50 questions against both the fine-tuned local SLM and the cloud Gemini API.

#### [NEW] `slm-rag-benchmark/scripts/benchmark_slm_vs_cloud.py`
This script will execute the comparison and generate a report covering:
*   **Latency:** Average generation time (ms) per query.
*   **Tokens/Second:** Throughput comparison.
*   **Accuracy:** A programmatic check (or LLM-as-a-judge check) to ensure the extracted answer matches the ground truth from the test set.
*   **Output:** Writes results to `results/benchmark_report.md`.
